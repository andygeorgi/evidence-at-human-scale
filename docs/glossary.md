# Glossary

The [paper](paper/README.md) and the [contracts](../contracts/README.md) use these terms as defined here. Where a word has more than one meaning, each meaning is listed separately.

| Term | Meaning |
| --- | --- |
| **Acknowledgement** | A record that a mandatory notification was received. It records receipt and does not resolve the obligation, which stays tracked. |
| **Admission** | The step at which a registered producer's record enters the registry. It establishes that the envelope and kind are admissible, never that the content is true. *Assistant-mediated admission* is admission through the assistant workspace and the registry. Existing native safety controls keep their own authorized routes outside it. |
| **Approver** | The person who issues an exact approval of one proposal, or a bounded grant (C06 `issuer`). The approver and the requestor are distinct roles, and no contract treats them as the same. One person may hold more than one role only where the domain's policy explicitly allows it, and each record still names the role in which the person acted. The separation of roles is a domain parameter (DP022, UNSET). |
| **Authoritative target** | The system whose own state decides what actually happened. A receipt is verified against that state, never against the executor's status. |
| **B_time, B_cost** | The task time budget (critical path) and the cost budget (full task lifecycle) declared before deployment. |
| **Bounded grant** | A C06 delegation that authorizes a predefined class of actions within explicit scope, limits and lifecycle, without a fresh approval for each instance. The worked example's identifiers call it a class grant (`GRT-CLASS-HOLD`). |
| **C01–C07** | The seven contracts: C01 Context, C02 Evidence, C03 Selection, C04 Decision packet, C05 Action proposal, C06 Delegation and C07 Execution receipt. See the [contracts](../contracts/README.md). |
| **Child task** | A task or specialist that the orchestration starts for part of a larger task. Calls, tokens, time, retries and spend are limited once for the whole task and shared by its child tasks. They are not set separately for each child. |
| **Claim reference / payload reference** | The two tagged alternatives for pointing at evidence. A claim reference names the exact record version and the claim ID. A payload reference names the exact version and an explicit payload location, and never invents a claim ID. |
| **Commit** | The moment an action takes effect. At commit the executor rechecks current permission and revocation, evidence, policy, target state, and the per-action and cumulative limits. An earlier approval does not replace these checks. |
| **Common origin** | Two derivations that share a root record. Their agreement is not independent corroboration. |
| **Confirmed-effect policy** | The documented policy under which allowance may be restored: only on authoritative reconciliation, never on timeout or lease expiry alone. |
| **Context** | Three meanings, kept apart. *Decision context*: the reusable unit of the architecture, the versioned set of authorized, attributable information selected for one decision, synthesized within limits and released as a decision packet. *C01 Context*: the contract that records the requesting principal, task, purpose, entities, time and policy. *Model context*: what is placed in front of a model, which may contain only evidence that the principal was already authorized to read. |
| **Control plane** | The controls that apply to every stage and path: identity, authorization, purpose, domain policy, the inventory of sources, models and tools, freshness, budgets and delegation. |
| **Decision Owner** | The person who reviews the decision packet and owns the decision, also called the accountable reviewer. Where the domain's policy explicitly allows it, the Decision Owner is also the approver. The worked example does this and records it in its `registry.json`. |
| **Decision packet** | The C04 versioned review object, bound to an exact context and selection. It separates supported claims, labeled inferences, recommendations, conflicts, uncertainty, gaps, obligations and unexecuted proposals. It does not authorize any action. |
| **Deterministic finding** | A C02 record of the result of a declared rule, at a stated version, applied to stated inputs. |
| **Documentation contract** | One of the seven contracts C01–C07. It states what a unit of information must carry and how it is referenced, in prose and in the schema bundle. It is documentation and not a deployable interface. The schema checks structure only; implementation work and domain expertise are still needed. |
| **Domain parameter** | A value the domain owner must supply: source authority, freshness, safe states, thresholds and the like. An unresolved parameter blocks the deployment decision or operation that depends on it. It does not block publication of the reference architecture, and an assistant may never invent a value to fill the gap. |
| **EN01–EN05** | The five public records the paper cites, all from Icelandic public authorities. Each is a dated, single source, not evidence of a systemic failure. See the [public records](../references/public-records.md). |
| **Evaluation case** | One of the 37 mutated copies of the worked example in [`examples/13-evaluation-cases`](../examples/13-evaluation-cases/README.md). Each must produce exactly the check codes it declares. A case belongs to the repository's own checks. It is not one of the EV01–EV12 evaluation tests, and it is not one of their 70 fixtures. |
| **Evidence** | An attributable, scoped assertion. It is not guaranteed to be true. |
| **Evidence class** | The kind of support a statement has: a real public record, an internal engagement record, a synthetic illustration, a repository check, or something that is not available. One class is never presented as another. See [claims and limits](claims-and-limits.md#evidence-classes-kept-apart). |
| **Evidence ledger** | The role of keeping a durable record of admitted evidence versions. In this architecture the registry plays that role, so there is one store and no second ledger. A decision packet is not a substitute for it, and neither is a product's managed memory. |
| **EV01–EV12** | The twelve evaluation tests defined for the architecture. None has been run, and all are NOT ASSESSED. See the [oracles](../evaluation/oracles.md). |
| **Executor** | The component that performs an approved action, also called the action gateway. At commit it rechecks permission, evidence, preconditions and limits against the current state before it submits the action. Its own status is never evidence of the outcome. Only the authoritative target decides that. |
| **Field group** | A numbered part of a contract, written like `C03-G05` (contract 3, group 5). The seven contracts have 41 field groups. |
| **Fixture** | A synthetic case with fixed inputs and a fixed expected result. The word covers two different sets. The *failure fixtures* of the repository's own checks, the 64 invalid schema examples and the 37 evaluation cases, are run and tested. The 70 *evaluation fixtures* of EV01–EV12 each add an expected oracle, an accountable owner, metrics and a gate, and are NOT ASSESSED. |
| **IN01–IN04** | The author's four internal engagement records, which are not published. None measures the benefit of this architecture. See the [engagement records](../references/engagement-records.md). |
| **Independent mandatory path** | The deterministic route from the registry through detection, an authorized notification and a queue to acknowledgement or escalation. It does not depend on an LLM being available. |
| **Lineage** | The directed, acyclic derivation ancestry of a record, plus separately typed relationships (contradiction, supersession, validation, invalidation), each naming the actor who asserted it. |
| **Matched baseline** | A simpler way of doing the same work, against which the architecture has to be compared: the native or current workflow, deterministic grouping and templates, or simple synthesis with zero specialists, matched on task, risk, scope and acceptance criteria. The catalogue defines 12 matched baseline records. All are NOT ASSESSED. |
| **Missingness labels** | The seven states that must not collapse: `missing`, `not_retrieved`, `inaccessible`, `unavailable`, `negative`, `not_assessed`, `stale`. See [chapter 8](paper/08-uncertainty.md). |
| **Model inference** | A C02 record that a model produced an interpretation. It does not establish that the interpretation is true. |
| **Native safety controls** | Existing deterministic safety controls that keep their established authorized routes outside assistant-mediated admission (see *Admission*). |
| **NOT RUN** | Executable with what exists, and not performed. |
| **NOT ASSESSED** | The evidence, environment, participants or input that an evaluation or a check needs do not exist, so nothing was evaluated. It is never an automatic pass. The evaluation catalogue and the validators in `scripts/` both use it. It differs from the source-level label `not_assessed`, which means that a check or assessment of an input was not performed. |
| **`not_executed_verified`** | The C07 receipt state for a *verified no-effect*: authoritative confirmation, by rejection, failure before effect or cancellation, that the action caused no business effect for this attempt, target and scope. A timeout, a missing response or a gateway rejection on its own is never this state. This is its only name; "verified no-effect" is a plain-language gloss. |
| **Oracle** | The explicit expected result of an evaluation test or fixture. |
| **Qualified** | Two senses, kept apart. *Qualified information* is available but carries an explicit limitation: it is stale, partial, or from a source that did not answer. It supports a limited review with its limits visible, and never a clean negative. A *qualified deterministic template* is a fallback with no model in it, checked and accepted for use when the assistant model is unavailable. |
| **Recovery owner** | The named owner who acts on a failure. The [failure table](../architecture/action-and-degradation.md#full-failure-response-and-recovery-ownership) assigns an owner to each failure, and no other page keeps a separate list. |
| **RG01, RG02** | The two guidance and standards sources the paper cites for positioning only: the NIST AI Risk Management Framework and Article 14 of the EU AI Act. See [guidance and standards](../references/guidance-and-standards.md). |
| **Registry (governed)** | The store that retains admitted, immutable record versions. Two other things have a similar name, and neither is a store of evidence. The *ProducerRegistry* is the list of registered producers, registry versions and permitted evidence kinds. In the worked example, `registry.json` holds the example domain's own configuration: its producers, policies, permission decisions, who holds each role and the review log. |
| **Requestor** | The principal who asks for the packet (C01 `requesting_principal`). The requestor is a different role from the approver and from the Decision Owner. One person may hold more than one of these roles only where the domain's policy explicitly allows it. |
| **RUN / PASS, RUN / FAIL** | An evaluation row that was executed, with the command, the input and the output recorded. No row has this status yet. |
| **Scoped validation** | A validation record naming who assessed which exact target, by which method, when and within what scope. It does not establish universal correctness. |
| **Selection manifest** | The C03 record of what the system actually considered and retained, with coverage, exclusions, grouping reasons and missingness. |
| **Specialist** | An optional agent that receives an authorized task with explicit limits and returns results only through admission. The zero-specialist baseline is a complete architecture. |
| **Supersession / invalidation** | A correction supersedes an earlier record version and invalidates affected derivatives, packets, caches and pending approvals. |
| **UNSET** | The design of an evaluation is undefined, or a domain parameter has no value yet. |
| **Unknown outcome** | A C07 state in which the effects of an action remain unresolved. The reservation, or conservative accounting, is kept until authoritative reconciliation, and there is no blind retry. |
